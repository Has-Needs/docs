# Has-Needs Documentation

Has-Needs is a sovereign coordination protocol originating in disaster-response design. The current architecture is defined by a minimal semantic triplet, participant-controlled disclosure, receipt-only durable exchange evidence, local/emergent ontology, network-level non-enumerability, and community-tested transparent security mechanisms.

## Start here

**[Has-Needs Specification V1](./Has-Needs-Spec-v1.md)** is the canonical architecture and protocol working draft.

## Historical material

This repository contains more than a decade of design exploration. Older files are retained where they preserve useful rationale, scenarios, interface concepts, or research history. They are **non-normative** unless explicitly incorporated into Specification V1.

Where an older document conflicts with V1, **V1 governs**.

The PDFs `Has-Needs_Project.pdf` and `WhitePaper.pdf` are legacy pre-V1 snapshots and should not be treated as the current architecture.

## Current implementation status

The code repository contains experimental pre-V1 prototypes. Some code predates clarified invariants such as owner-scoped enumeration, `WORKING` terminology, canonical receipts, network non-enumerability, live trust vetting, and the current Trust Kernel update model. It should be treated as implementation research, not proof of specification conformance.
