# Has-Needs Documentation

Has-Needs is a sovereign coordination protocol originating in disaster-response design. The current architecture is defined by a minimal semantic triplet, participant-controlled disclosure, receipt-only durable exchange evidence, local/emergent ontology, and network-level non-enumerability.

## Start here

**[Has-Needs Specification V1](./Has-Needs-Spec-v1.md)** is the canonical architecture and protocol working draft.

**[Development Roadmap](./ROADMAP.md)** describes the shortest path from the current experimental implementation to a reviewable V1-conformant reference system.

## Document status

This repository contains more than a decade of design exploration. Older files are retained where they preserve useful rationale, scenarios, interface concepts, or research history. They are **non-normative** unless explicitly incorporated into Specification V1.

Useful supporting material includes:
- `Persona Files/` — scenario and stakeholder perspectives.
- `UI_Vision.md` — early interface exploration, including the Personal Globe, RGB visual language, and Data Story concepts.
- `jitterbug` material in the code repository — early transport/topology exploration.
- research and humanitarian background documents.

Where an older document conflicts with V1, **V1 governs**.

## Current implementation status

The code repository contains experimental pre-V1 prototypes. Some code predates clarified invariants such as owner-scoped enumeration, `WORKING` terminology, canonical receipts, and network non-enumerability. It should be treated as implementation research, not proof of specification conformance.
