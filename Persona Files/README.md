# Persona and Scenario Files

These files preserve stakeholder perspectives, use cases, and narrative experiments developed during the evolution of Has-Needs.

**Status: stakeholder scenarios / non-normative.**

They are valuable because they capture intended human outcomes that technical documents can flatten: survivor agency, reciprocal participation, emergency-manager workflows, migrant dignity, agricultural exchange, community formation, resource maps, and transitions from response to recovery.

Some language predates Specification V1 and may assume broader visibility, permanent logging, trust/reputation mechanisms, or implementation technologies that are no longer architectural requirements.

**Current architectural frame:** The Persona Manager acts as a concierge behind all user-created personas, keeping the owner's personal chain sacrosanct. Agency or community views contain only data contributed under authorized Needs, not direct access to citizen chains. At completion each participant independently provides optional comments and sets plaintext/encryption; all parties review the record and planned exposure before committing identical receipts. When a scenario conflicts with [Has-Needs Specification V1](../Has-Needs-Spec-v1.md), **V1 governs**. Scenario narratives preserve human context without creating protocol guarantees.
